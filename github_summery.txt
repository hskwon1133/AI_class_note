<appendix1 이미지 참고>
1. **로컬 / 클라우드 개념**
    1. 로컬 : 데스크탑으로 만들어 저장 가능
    2. 클라우드/원격/리모트 서버 : 외부 회사의 저장 공간에 저장.
    3. Github는 코드를 공유하는 데이터 클라우드 저장 공간 전체 공유,  나만 보기로 관리 가능
2. **소스트리 설치**
    1. 설치방법
        1. window 전용 다운로드 < install < bucket(일단 건너뛰기) < 체크된 대로, 권장처리 기준으로 다음 클릭 < email 기입 < SSH Key 여부 선택
3. **Github - Repo 만들기** 
    1. public/private : 코드 내용을 전체 공유, 개인관리로 지정 
    2. read me : 해당 repo에 대한 설명서
    3. add  license : 저작권 용도
4. **로컬 폴더 생성하기**
    1. 원격지와 연동할 폴더 생성
    2. **확장자 : 워드/한글/그림 등의 프로그램으로 열수 있는 코드. 원도우 > 기본앱 > 기본값 설정가능 (윈도우는 Setting이 다 되어 있음, ex. txt, png, ppt 등)
5. **로컬 - 원격지 클론으로 연동하기**
    1. 클론은 원격지에 폴더가 빈 공간이어야만 가능
    2. 원격지 소스 경로는 : Git 왼쪽 상단 [<> code]에서 copy 가능
    3. 로컬 폴더 카피 : cntl+shift+c
6. **파일 생성 후 커밋**
    1. 커밋 : 어떤 작업들이 있었는지, 어느 파일을 어떻게 작업 했는 지 알 수 있음.
    2. 커밋 지정으로 작업단위별 history추적 가능. 수정 전으로 되돌릴 수 있음.
    3. 수정하고자 하는 브랜치에서 선택 내용만 스테이지로 올리게 되면 선택 파일만 수정됨
    4. 이전 history로 돌리고 싶으면 해당 커밋 체크아웃(더블클릭, 우측 클릭 > 체크 아웃)
    5. 잘못된 내역도 기록으로 쌓아두는 것이 좋음. 과거 로그를 보기 위함.
7. **main 외에 new branch 생성하기**
    1. 일종의 작업 기록순으로 main과 용도별 브랜치 존재 
        - **오리지널 세계(보통 `main` 또는 `master` 브랜치)**: 손님들에게 실제로 보여주는 안전하고 완벽한 원본 파일입니다.
        - **평행 세계(새 브랜치)**: 원본을 그대로 복사해 와서, 마음껏 새로운 기능(새로운 캐릭터, 새로운 맵 등)을 만들고 실험해보는 안전한 연습장입니다. 이 평행 세계에서 아무리 에러가 나고 망가져도 **오리지널 세계는 아무런 타격을 입지 않아요!**
    2. 브런치 기준 폴더 확인 및 수정하려면 해당 브랜치 최근 시점에서 진행
    3. main 외에 목적에 맞게 상황을 만들어 관리를 함
    4. 왼쪽 커밋은 항상 main이 아니라 체크아웃한 브랜치 기준임
8. **push & pull**
    1. 브랜치 단위로 연동 
    2. push : 로컬  →  원격
        1. 브랜치 각각 push 가능, 추가 수정 후 cover도 가능.
        2. 이름이 같아도 리모트로 가능 (리모트 브랜치 생성 또는 원래 있던 리모트에 지정하기)
    3. pull : 로컬 ← 원격 
        1. main으로 병합 또는 원격의 파일이 더 많아 원격으로 동기화할 필요가 있을 시 시행
9. **merge**
    1. 원격 Github에서 main에 new branch를 병합 (main으로 합쳐짐)
    2. pull requests 또는 자동 생성된 pull request로 진입 가능
    3. able to merge 여부 확인
    4. 메세지 전달 후 merge 신청
    5. repo 승인자에게 merge 승인을 받기 (main으로 merge 완료 되면 보라색으로 연결 링크 표기됨)
    6. 이후 pull로 로컬로 가져와서 추가 작업 시행 가능
    7. main으로 병합 후 완료가 되었다면 오리지널 외에 작업한 브랜치들은 삭제 가능
